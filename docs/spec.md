# 頭痛ーる気圧通知アプリ 仕様書

## 概要

- 本アプリは、頭痛ーるの気圧情報をもとに、毎朝メッセージサービス（Slack または LINE）に「今日一日の頭痛リスク」をシンプルに通知することを目的とする。
- 初期リリースでは、まず Slack（Incoming Webhook）による通知実装を行い、LINE Messaging API への対応は将来の拡張候補とする。
- 初期リリースの最小構成は以下とする。
  - 対象ユーザー: 1人（自分）固定
  - 対象地点: 1地点固定（頭痛ーるの地点IDで指定）
  - 通知タイミング: 1日1回（毎朝7:00 JST）
  - 通知条件: 頭痛ーるの気圧レベルが、指定したしきい値以上になる時間帯が1つでもある場合だけ通知
- 実装言語は TypeScript、実行環境は Docker コンテナを用いた Cloud Run Jobs とする。

## ユースケース

### 想定ユーザー

- 自分自身（またはごく少数の家族など）
- 日々の気圧変化による体調への影響を把握したいユーザー

### 利用シナリオ

1. （Slack構成）ユーザーは一度だけ、Slackワークスペースで通知先チャンネルを決め、Incoming Webhook URL を発行しておく。
2. （LINE構成・将来）ユーザーは一度だけ、LINE公式アカウントを友だち追加し、開発者側でそのユーザーIDを取得・設定する。
3. ユーザーは特に操作を行わずとも、毎朝決まった時間（デフォルト: 7:00）に、「今日一日の頭痛リスク」が届く。
4. 通知は、頭痛ーるの気圧レベルが指定しきい値以上になる時間帯が存在するときのみ送られる。何も問題なさそうな日は通知されない。

## システム構成（最小構成）

### 全体構成概要

- Google Cloud Platform 上で、以下のコンポーネントのみを利用する:
  - Cloud Run Jobs: TypeScript で実装したバッチコンテナを定期実行する。
  - Cloud Scheduler: 毎日7:00（Asia/Tokyo）に Cloud Run Job を起動するトリガーを設定する。（※Cloud Run Jobs側の組み込みスケジュール機能を使う構成でもよいが、本仕様では Cloud Scheduler を前提とする）
  - Secret Manager: 通知先サービス（Slack/LINE）のシークレットを安全に保管する。
- 外部サービス・API:
  - 頭痛ーる API: 指定地点の時間別気圧データを取得する。
  - Slack Incoming Webhook API: Slack チャンネルにメッセージを送信する（初期リリース）。
  - LINE Messaging API: 対象ユーザーのLINEアカウントにプッシュメッセージを送信する（将来の拡張候補）。

### コンポーネント一覧

- バッチアプリケーション（TypeScript）
  - 実行環境: Node.js (LTS) on Docker
  - 役割:
    - 設定・シークレットの読み込み
    - 頭痛ーる API から当日の気圧情報を取得
    - 通知判定ロジックを実行
    - 条件を満たす場合に、設定された通知先（Slack または LINE）にメッセージを送信
- Cloud Run Job
  - コンテナイメージ: 上記バッチアプリのビルド成果物を含むDockerイメージ
  - タスク数: 1（並列実行なし）
  - タイムアウト: 数分程度（初期値: 5分を想定）
- Cloud Scheduler
  - スケジュール: 毎日 7:00（Asia/Tokyo）
  - ターゲット: Cloud Run Job 実行エンドポイント
  - リトライ: 初期はシンプルさを優先し「リトライなし」とする
- Secret Manager
  - 通知先サービスに関するシークレット（Slack Webhook URL / LINEチャネルアクセストークンなど）を保存し、Cloud Run Jobs 実行時に参照可能にする。

## 外部サービス・API

### 頭痛ーる API（概要）

- エンドポイント（例）:
  - `GET https://zutool.jp/api/getweatherstatus/{place_id}`
- パラメータ:
  - `place_id`: 頭痛ーるが定義する地点ID（都道府県ID+市区町村IDの連結など）。本アプリでは1地点のみ設定。
- レスポンス（抜粋イメージ）:
  - `place_name`: 地点名
  - `today`: 当日の時間別データ（0〜23時の配列）
    - 各要素:
      - `time`: 時刻（"0"〜"23"）
      - `pressure`: 気圧[hPa]
      - `pressure_level`: 頭痛ーる独自の気圧レベル（0〜4）

### Slack Incoming Webhook（概要・初期リリース）

- 利用するエンドポイント:
  - `POST {Slackから発行されたIncoming Webhook URL}`
- リクエスト仕様（概略）:
  - ヘッダ:
    - `Content-Type: application/json`
  - ボディ（例）:
    - `text`: 通知本文（テキスト）
    - 必要に応じて `blocks` などのリッチフォーマットも利用可能だが、初期リリースでは `text` のみを想定する。

### LINE Messaging API（概要・将来拡張）

- 利用する主なエンドポイント（想定）:
  - プッシュメッセージ送信:
    - `POST https://api.line.me/v2/bot/message/push`
- リクエスト仕様（概略）:
  - ヘッダ:
    - `Authorization: Bearer {LINEチャネルアクセストークン}`
    - `Content-Type: application/json`
  - ボディ（例）:
    - `to`: 通知対象ユーザーの userId
    - `messages`: メッセージオブジェクトの配列（`type: "text"`, `text: "..."` など）

## 機能要件

### 1. 気圧データ取得

- 対象日時:
  - 「当日0〜23時」の `today` 配列を対象とする。
- 対象地点:
  - 環境変数で指定された `ZUTOOL_PLACE_ID` のみを対象とする。
- 処理要件:
  - Cloud Run Job 起動時に、1回だけ API コールを行う。
  - APIレスポンスのうち、`today` 配列と `place_name` を使用する。
  - 取得失敗時（ネットワークエラーや5xxなど）は、ジョブを「失敗」として終了させる。

### 2. 通知判定ロジック

- 使用する指標:
  - 各時間帯の `pressure_level`（0〜4）
- しきい値:
  - 環境変数 `PRESSURE_LEVEL_THRESHOLD` で指定する。
  - 未指定の場合のデフォルト値は `3`（頭痛リスクが高いレベルとみなす）。
- 判定対象期間:
  - 当日0〜23時の全時間帯を対象とする。
- 通知条件:
  - 判定対象期間の中に、`pressure_level >= PRESSURE_LEVEL_THRESHOLD` を満たす時間帯が1つでも存在する場合、「本日中に頭痛リスクが高まる時間帯がある」と判定し、通知処理（Slack / LINE）を行う。
- 通知しないケース:
  - 上記条件を満たす時間帯が1つもない場合は、通知処理を行わずジョブを正常終了とする。

### 3. 通知（Slack / LINE）

- 通知先:
  - Slack 構成: 単一の Slack チャンネル（Incoming Webhook が紐づく先）。
  - LINE 構成: 単一のユーザーID（環境変数 `LINE_USER_ID` などで指定）。
- メッセージ内容（例・方針）:
  - タイトル行:
    - 「【頭痛ーる予報】本日の頭痛リスク」
  - 本文:
    - 対象地点名（例: 「地点: 東京都町田市」）
    - 本日中に `pressure_level >= しきい値` となる時間帯の一覧（例: 「09時, 13時, 20時 で注意レベル」など）
    - 簡単なコメント（例: 「気圧変化に注意してください」など）
  - メッセージはシンプルなテキスト1通とし、Slack/LINE いずれの場合も、リッチなUIは初期構成では行わない。
- 送信要件:
  - Slack 構成: Incoming Webhook への POST が成功（2xx）した場合のみ「成功」とみなす。
  - LINE 構成: LINE API 呼び出しが成功（2xx）した場合のみ「成功」とみなす。
  - 4xx/5xx の場合はログを出力し、ジョブを「失敗」として終了させる。

#### 併用時の挙動

- Slack 関連の設定（`SLACK_WEBHOOK_URL`）が有効な場合は Slack へ通知を送信する。
- LINE 関連の設定（`LINE_USER_ID` および `LINE_CHANNEL_ACCESS_TOKEN`）が有効な場合は LINE へ通知を送信する。
- 両方の設定が有効な場合は、**同一内容の通知を Slack と LINE の両方へ送信する**。

## 非機能要件

### 可用性・信頼性

- ジョブ実行頻度: 1日1回のため、高いスループットは不要。
- Cloud Scheduler のリトライ設定は「なし」とし、失敗時は手動で再実行する簡易運用とする。
- Cloud Run Jobs 側のタスクリトライも初期は無効または最小限（1回）とし、重複通知を避ける。

### パフォーマンス

- 1回のジョブ実行時間は数秒〜数十秒程度を想定。
- タイムアウトは余裕を見て 5分程度に設定するが、通常はそこまでかからないこと。

### セキュリティ

- シークレット（Slack Webhook URL, LINEチャネルアクセストークン等）は Secret Manager で管理し、ソースコードやコンテナイメージ内に平文で含めない。
- Cloud Run Jobs 用サービスアカウントには、Secret Manager の読み取り権限など、必要最小限のIAMロールのみを付与する。

## 設定およびシークレット

### 環境変数（例）

- `ZUTOOL_PLACE_ID`
  - 説明: 頭痛ーるAPIで使用する地点ID。
  - 必須: はい
- `PRESSURE_LEVEL_THRESHOLD`
  - 説明: 通知のしきい値となる気圧レベル（0〜4）。
  - 必須: いいえ（未指定時は `3` を使用）
- `LINE_USER_ID`
  - 説明: 通知対象となるLINEユーザーの userId（LINE構成で使用）。
  - 必須: いいえ（Slackのみ利用する場合は不要）
- `NOTIFICATION_TARGET`（将来）
  - 説明: 通知先サービスを切り替えるためのモード値（例: `slack` / `line`）。初期は `slack` 固定で実装し、環境変数は後日導入でもよい。

### シークレット（Secret Manager）

- `SLACK_WEBHOOK_URL`
  - 説明: Slack Incoming Webhook の URL。初期リリースで必須となる。
  - 利用方法: Cloud Run Jobs から環境変数として注入し、アプリの通知処理で利用する。
  - 備考: Slack のみ利用する場合は、この設定のみで通知が完結する。LINE 関連の設定も行った場合は、Slack と LINE の両方へ通知される。
- `LINE_CHANNEL_ACCESS_TOKEN`
  - 説明: LINE Messaging API 呼び出しに使用するチャネルアクセストークン（LINE構成で使用）。
  - 利用方法: Cloud Run Jobs から環境変数として注入、またはアプリ起動時にSecret Manager API経由で取得する。

## 運用・監視

- ログ出力:
  - 少なくとも以下のイベントを構造化ログとして出力する。
    - ジョブ開始・終了
    - 頭痛ーるAPI呼び出し結果（ステータス、失敗時の理由）
    - 通知判定結果（通知する/しない、対象時間帯一覧）
    - 通知API呼び出し結果（Slack/LINE 共通、成功/失敗、失敗時のエラー概要）
- 失敗検知:
  - Cloud Run Jobs の実行結果（成功/失敗）をダッシュボードで確認できるようにする。
  - 初期はアラート設定は必須とせず、必要になった段階で Cloud Monitoring のアラートポリシーを追加する。

## 今後の拡張候補

- 複数ユーザー対応（ユーザーごとに地点やしきい値を変更可能にする）。
- 1日複数回の実行や、気圧急変時のみ追加通知を行う高度なロジック。
- Webhook を用いた LINE ボット機能（ユーザーがLINE上から地点やしきい値を変更できるようにする）。
- データストアを導入し、過去の通知履歴や気圧履歴を蓄積して可視化する。
